# Cyber Escape Room

A Python command-line escape room that simulates a blue-team cybersecurity investigation. Explore a sequence of rooms, analyze evidence files, recover four investigation tokens, and submit a final verification message authenticated with HMAC-SHA256.

The project combines practical cybersecurity-style investigation with core Python concepts: parsing structured data, validating malformed input, decoding encoded configuration values, regular expressions, graph traversal, and cryptographic message authentication.

## Overview

You are part of a blue-team unit responding to a simulated security incident. Each room represents a different defensive security task. Inspect its evidence file, interpret the results, and collect the corresponding token. The incident board in the lobby shows which tokens have been collected.

The game is designed to work with the supplied data pack. Its solutions are derived from the files at runtime rather than hardcoded into the room logic.

## Rooms and Challenges

| Room | Evidence file | Investigation task | Token |
|---|---|---|---|
| **SOC Triage Desk** | `auth.log` | Validate SSH authentication records, count failed attempts by IPv4 /24 subnet, and identify the top source IP in the winning subnet. | `KEYPAD` |
| **DNS Closet** | `dns.cfg` | Read the `token_tag`, select the authoritative encoded hint, reverse its declared encoding, and extract the final word. | `DNS` |
| **Vault Corridor** | `vault_dump.txt` | Find the valid `SAFE{a-b-c}` candidate for which `a + b = c`. | `SAFE` |
| **Malware Lab** | `proc_tree.jsonl` | Skip malformed records, build the process relationship graph, and trace the process that meets the exfiltration-command criteria. | `PID` |
| **Final Gate** | `final_gate.txt` | Read the group configuration and token order, construct the message, and calculate its HMAC-SHA256 digest. | Final verification |

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/VIKHYATH-KS/Cyber-Escape-Room.git
cd Cyber-Escape-Room
```

### 2. Check your Python version

```bash
python --version
```

On systems where Python 3 is invoked as `python3`, use that command in the examples below.

### 3. Start the game

From the repository root, run:

```bash
python escape.py
```

The game starts in the Intro Lobby and writes a transcript to `run.txt` by default. Enter `help` in the game for the available commands.

## Running the Game

The entry point supports optional arguments for the starting room, the data directory, and the transcript path.

```bash
python escape.py --start intro --data data --transcript run.txt
```

Arguments:

| Argument | Description | Default |
|---|---|---|
| `--start` | Room to enter when the game starts. | `intro` |
| `--data` | Directory containing the evidence and configuration files. | `data` |
| `--transcript` | File that records the game interaction and evidence output. | `run.txt` |

Use the room names to move around: `lobby`, `soc`, `dns`, `vault`, `malware`, and `final`.

## Commands

## How the Final Gate Works

The Final Gate reads its settings from `data/final_gate.txt`. The file provides:

- `group_id`: the identifier for the assigned group.
- `token_order`: the order in which token values must be concatenated.
- `hmac_key`: the key used for message authentication.

Once all required tokens are present, the game constructs the message in this form:

```text
<group_id>|<token1>-<token2>-<token3>-<token4>
```

The token values are placed in the exact order specified by `token_order`; the order should not be assumed or hardcoded. The program then calculates an HMAC-SHA256 digest using the UTF-8 encoding of both the key text and message.

The transcript includes the required verification fields:

```text
FINAL_GATE=PENDING
MSG=<group_id|token1-token2-token3-token4>
HMAC=<64-character lowercase hexadecimal digest>
```

The `hmac_key` is configuration input, not the expected digest. The digest is calculated at runtime.

## Running Tests

The project uses Python's built-in `unittest` framework. From the repository root, run the complete test suite:

```bash
python -m unittest discover -s tests -v
```

The tests cover the room logic, parsing and validation of evidence, malformed records, token generation, game state and save/load behavior, and the Final Gate's HMAC calculation.

## Implementation Notes

- **Data-driven behavior:** tokens, the selected DNS hint, and the Final Gate token order are determined from the supplied files.
- **Input validation:** malformed log entries, invalid DNS configuration, malformed process records, and invalid SAFE candidates are handled explicitly.
- **Graph traversal:** the Malware Lab builds process relationships and uses visited tracking during traversal to avoid getting stuck in cycles.
- **Evidence in the transcript:** room analysis emits tagged token and evidence lines that can be checked independently.
- **Save and load:** game state, collected tokens, inventory, current room, and hint progress can be saved and restored.
- **Shared hints:** Radio scripts and reusable fixed strings are centralized in `escaperoom/constants.py`.
